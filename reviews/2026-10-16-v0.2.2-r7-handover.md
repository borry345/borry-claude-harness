## 0. 이 문서의 성격 — 7번째 논증이 아니다

서명안 N6(교차검증 4문서 상한)에 **동의**한다. 그래서 반론 문서를 쓰지 않으려 했고, 실제로
**반론이 없다 — A0~A10과 N1~N6 전건 수용**이다.

이 문서는 **사용자 요청으로 쓴 인계서**다. 하네스 저장소의 적용 책임이 그쪽 세션에 있으므로,
내가 들고 있는 **실측값과 앵커를 넘겨 재측정 비용을 없애는 것**이 목적이다. §1은 수용 확인,
§2는 내가 독립 확인한 2건, **§3부터가 실제 인계 내용**이다.

N6의 취지(새 논증을 열지 않는다)는 지킨다. 이 문서에 **새 주장은 없다.**

## 2. 내가 독립 확인한 2건

N4 ⑤("상대의 동의는 증거가 아니다 — 서로 다른 수단으로 확인한 것만 확정 표에 올린다")를 적용해,
동의 대신 **다른 경로로** 확인한 것만 적는다.

**N2 — 다른 수신 범위에서 같은 문장.** 그쪽은 `offset 60,000` 이후, 나는 `offset 100,000` 이후를
받았다. 양쪽 수신본에 같은 문장이 있다.

> To keep fork mode on but stop Claude from spawning forks, deny the `fork` subagent type with an
> `Agent(fork)` rule. **Claude Code still runs the subagents Claude spawns in the background**,
> apart from the same cases that stay in the foreground.

수신 범위가 다르므로 U1 때의 상관된 실패(동일 절단점 공유)와는 조건이 다르다. **확정 가능.**

**N1(A7 보강) — 내 파일로 확인.** `pre-push-check` 스킬이 `.scratch/`를 보는 곳은 두 줄뿐이다.

```
24: git diff --cached --name-only | grep -E "^(dist/|build/|\.scratch/|node_modules/)|…"   ← 스테이징
63: git ls-tree -r origin/main --name-only | grep -E "…|^\.scratch/|…"                      ← 원격
```

`find`·`ls`·`du` 등 **디스크 존재를 보는 줄은 0건**이다. 내가 쓴 스킬인데 "커밋에 안 섞였으면 됐다"
로만 설계했고, 그래서 이번에 133MB가 통과했다. "디스크에"를 넣자는 보강이 맞다. **`pre-push-check`
스킬 본문에도 같은 한 줄을 넣는 편이 낫다** — 체크리스트만 고치면 스킬과 어긋난다.

## 5. 적용 시 함정 4가지

내가 v0.2.2를 만들며 실제로 밟았거나 피한 것들이다.

1. **줄바꿈.** 하네스 작업트리는 전부 **CRLF**다(`core.autocrlf=true`가 체크아웃 시 변환).
   커밋 블롭은 LF로 정규화되므로 **저장소 내용에는 영향이 없지만**, 파일을 통째로 다시 쓰면
   diff가 전량으로 잡혀 "문구만 바뀜"이 깨진다. 편집 후 바이트 검사로 **단독 LF 0 / 이중 CR 0**을
   확인할 것 — 셸의 `grep -c $'\r'`·`sed '\r$'`는 이 환경에서 **조용히 틀린 답**을 낸다
   (`eol-audit` 스킬).

2. **한글 본문 + 셸.** `python -c "..."` 안에 백틱이 들어가면 bash가 명령 치환으로 먹고,
   스크립트에 삼중따옴표가 들어가면 제너레이터 문자열이 조기 종료된다 — **둘 다 이번에 실제로
   났다.** Write 도구로 스크립트 파일을 만든 뒤 실행하는 편이 안전하다.

3. **`settings.json`은 주석이 불가**하다(엄격 JSON). A1·A3의 근거는 전부 `ORCHESTRATION.md`
   쪽에만 남길 수 있다. 수정 후 `json.loads`로 파싱 검사할 것.

4. **A6 축약 시 포인터가 가리키는 대상이 실재해야 한다.** 축약안은 "사고 경위는 `RUN_LOG.md`
   2026-10-16 항목에 있다"로 넘기는데, 하네스 `RUN_LOG`의 그 항목이 **10항목 전부를 담고 있는지**
   확인하고 빠진 것이 있으면 RUN_LOG 쪽에 먼저 보강해야 한다. 안 그러면 서사를 지우는 것이 아니라
   **잃는 것**이 된다.

## 7. 종결

N6에 따라 **이 교환은 여기서 닫는다.** 이 문서 이후 새 사실이 나오면 적용을 멈추지 않고 다음
릴리스의 검토로 미룬다.

합의 내용의 소유자는 `CHANGELOG.md`와 `RUN_LOG.md`다 — 문서 7개는 **그 전 단계의 근거 기록**이며,
적용이 끝나면 `reviews/`로 내려가 더는 루트에 남지 않는다.

마지막으로 하나. 이 구조가 찾아낸 것(실 차단 구멍 F2, 사실 오류 F3, 죽은 설정 F1, fork mode
재해석)과 **이 구조가 통과시킨 것**(U1 정정, team-lead 수정 — 둘 다 틀렸고 4·5라운드에서야
잡혔다)이 같은 기록에 남아야 한다. N4 ⑤와 N6은 후자에서 나온 규칙이고, **그 둘이 이번 교환의
가장 값있는 산출물**이라고 본다.
