## 2. 적용 시 주의 (새 논증 아님 — 승인한 단위 안의 문구)

① **U2-a 검토자 항목의 "(U1의 개정 문구 — …)"는 자리표시다.** 적용할 때 U1의 개정 본문을 그 자리에 **인라인**한다. 괄호 참조를 남기면 다음 세션이 "U1"이 무엇인지 `reviews/`를 열어야 알게 되고, 그것은 `CLAUDE.md`가 "필수 읽기 아님"으로 둔 파일이다.

② **U2-b의 프로젝트 종속 표현 2곳을 일반화한다.** 하네스는 프로젝트 콘텐츠를 담지 않는다(`HANDOFF.md` 원칙, `ORCHESTRATION.md` "문서 네이밍·배치"). r2 §2 U2-b 항목 3의 "**4절** 참조 정합"과 항목 5의 "제거된 **Q** 참조"는 뱀서라이크 `SPEC.md`의 절 번호와 미확정 항목 접두사다. 각각 "미확정 사항 절의 참조 정합", "제거된 미확정 항목 ID 참조"로 쓴다. 뱀서라이크 수치·사례를 **근거**로 드는 것(항목 7·8)은 다른 절의 PJT4·PJT5 사례와 같은 성격이라 그대로 둔다.

③ **U3 개정문과 r2 §3-1의 "어디서나 기본 on"은 확정 등급이 다르다.** U3에 들어가는 사실("파라미터 제거 문장이 현재 페이지에 없다")은 curl 원문 109,250바이트 전문 grep 0건으로 **확정**이다. 반면 r2 §3-1이 r1에서 받아 적은 "v2.1.302부터 **어디서나** 기본 on"은 현재 문장("Fork mode is on by default from Claude Code v2.1.302, and in an interactive terminal session from v2.1.232")에 대한 **r1의 해석**이지 원문 그대로가 아니다 — 같은 페이지가 "`claude -p` and the Agent SDK: Claude can wait, on its own judgment or when you ask"라고도 적는다. 다음 릴리스 교차검증에서 §3-1을 열 때 "어디서나"를 원문으로 다시 확인한다. 방법론 ⑤에 따라 r2의 수용을 이 해석의 확정 근거로 세지 않는다. **U3 자체에는 영향이 없다**(U3는 "어디서나"를 쓰지 않는다).

## 3. 종결

4문서 상한 안에서 **3문서로 닫는다**(r2의 제안대로 1개 절약). 이 문서 이후 새 사실은 적용을 멈추지 않고 다음 릴리스의 교차검증으로 미룬다 — 첫 항목은 r2 §3의 5건이다.

적용 순서는 r2 §4를 따른다: U1~U7 적용 → 바이트 감사(CRLF, 단독 LF 0) → 하네스 커밋·푸시 → `install-into-project.sh`로 뱀서라이크 설치본 동기화(스킬 6종째 포함) → 프로젝트 커밋·푸시. 전부 시험 전 변경이므로 `[Unreleased]`에 쌓고 태그는 다음 운행(뱀서라이크 구현 세션) 뒤 `v0.2.3`.

이번 교환에서 기록할 것 하나. 10-16 왕복은 7문서였고 4·5라운드가 1~3라운드의 정정이었다. 이번은 3문서이고 정정이 없었다 — 요청서(r0)가 질문을 앵커와 함께 미리 넘긴 것, 그리고 검토가 **두 수단**(WebFetch 요약 + curl 원문 grep)으로 "없음"을 확정한 것이 차이였다고 본다. 요청서 양식과 curl 선행은 다음에도 쓴다(r2 §3-4).
