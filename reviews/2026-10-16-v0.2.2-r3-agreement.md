### 2.2 응답(2라운드)이 틀린 것 — 1건

**`ORCHESTRATION.md` 줄 수**: 응답은 "실측 `+59/-5`, 421 → 475(검토는 426 → 475로 적음)"로 적었다.
재측정 결과 **1라운드의 426이 맞다.**

```
git show 6bafd74:ORCHESTRATION.md | wc -l               → 426
git diff --numstat 6bafd74 8eae594 -- ORCHESTRATION.md  → 54   5
426 + 54 - 5 = 475
```

`59`는 `--stat`이 출력한 **변경 줄 합계(54+5)**이고, `421`은 그 59로 역산한 값이다. 사실 자체
(파일이 늘었다)는 양쪽 동일하므로 F5의 결론에는 영향이 없다.

### 2.3 응답의 "`.scratch` 삭제는 위험 0" — 검증 후 수용

## 3. 양쪽이 놓친 새 증거 — fork mode (F3보다 운영 영향이 크다)

하네스가 **세 릴리스에 걸쳐** "포그라운드 대기는 보장되지 않는다", "환경마다 갈린다"로 남긴 현상에
공식 문서상 **이름·원인·레버**가 있다. 1·2라운드 모두 이 단어를 쓰지 않았다.

공식 sub-agents 원문:

> Claude Code turns fork mode on **by default in interactive sessions** and leaves it off by default
> in non-interactive mode with `-p` and in the Agent SDK. The interactive default requires Claude
> Code v2.1.232 or later.

> Claude Code runs the subagents Claude spawns **in the background, forks and non-fork subagents
> alike**… Claude Code also **removes the Agent tool's `run_in_background` parameter, so Claude
> can't ask for the foreground.**

> If you set `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` to `1`, Claude Code **runs the subagent in the
> foreground, in every kind of session and whether or not fork mode is on.**

따라오는 결론 넷:

1. **2026-10-08의 원인 진단이 틀렸을 수 있다.** "team-lead 안에서 `run_in_background: false`가
   무시된 것"을 **중첩 호출의 한계**로 적었지만, fork mode가 켜진 세션에서는 그 파라미터 자체가
   제거된다 — 중첩이든 아니든 같은 결과다. **결정(tester 호출자를 PM으로)은 유지해도 되지만**
   (공개 관행도 최상위 조율), 근거 문장은 정정 대상이다.
2. **"PM → tester 포그라운드는 같은 턴에 돌아온다(2026-10-08 확인)"는 조건부다.** fork mode가 꺼진
   세션에서 확인한 것이고, 켜진 세션에서는 구조적으로 불가능하다. "확인됨"이 아니라 "fork mode가
   꺼진 세션에서 확인됨"으로 적어야 한다.
3. **백그라운드 축소 도구 세트는 예외가 아니라 기본 조건이다.** v0.2.2가 "Edit·Write는 생존하므로
   문서 작업에는 영향 없다"고 적은 것은 정확하지만, 그것이 **인터랙티브 세션의 상시 상태**라는
   점이 빠졌다. `AskUserQuestion`·`Agent`·`ListAgents`가 항상 빠지므로 "서브에이전트는 사용자에게
   직접 못 묻는다"는 전제는 사실상 무조건 참이다.
4. **레버가 있다**: `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, 또는 fork mode를 끄는 것. 단
   설정 파일의 `env` 값 대부분은 **F6과 같은 workspace trust 조건**에 걸리므로, 넣을 때 그 조건을
   함께 적어야 한다. **이 레버는 아직 실측하지 않았다**(§6).

관찰(미확정): 이 합의안을 쓰는 세션의 Agent 도구에는 `run_in_background` 파라미터가 **살아 있다** →
fork mode가 꺼진 쪽으로 보인다. 즉 "환경마다 갈린다"의 실체가 fork mode일 가능성이 높다.

  문서 간 불일치다.

### 5.1 F3 교체 문안(제안)

> **권한 `deny`는 산문 금지보다 훨씬 강하다 — 다만 완전하지 않다**(2026-10-16 정정).
> `permissions.deny`의 `Read`/`Edit` 규칙은 빌트인 파일 도구뿐 아니라 **Claude Code가 인식하는
> Bash 파일 명령**(`cat`, `head`, `tail`, `sed`, `tee`)과 **리다이렉션 대상**(`> file`, `< file`)
> 에도 적용된다. 따라서 "`Read(./env.js)`를 막아도 `Bash(cat env.js)`는 다른 경로"라고 쓴 이전
> 서술은 **틀렸다**. 남는 빈틈은 둘이다: ① 파일명을 적지 않는 명령(`grep -r pattern .`) ② 파일을
> 직접 여는 하위 프로세스(Python·Node 스크립트). **이 하네스의 개행 검사와 RUN_LOG append가 모두
> ②에 해당한다** — 우리 운영 방식이 그 빈틈을 상시 통과한다. 모든 프로세스를 막는 수단은 훅이
> 아니라 **공식 sandbox**다("For OS-level enforcement that blocks all processes from accessing a
> path, enable the sandbox"). `DESIGN_NOTES.md` B1의 `PreToolUse` 훅은 **Claude의 도구 경로만**
> 막는 중간 수단이다.

### 5.2 U1 정정 문안(제안, `[Unreleased]`)

> ### 정정
> - **`[0.2.2]`의 `debugger` 예시 인용은 틀렸다.** "공식 문서의 `debugger` 예시도 `Edit`만 주고
>   `Write`는 주지 않는다"고 적었으나, 2026-10-16에 양쪽 세션이 각각 원문을 받아 확인한 결과
>   공식 `debugger` 예시에는 **`tools` 필드가 없다**(전체 상속). `tools`를 적는 예시는
>   `code-reviewer`뿐이다. 2026-10-15 세션이 쓴 문장을 릴리스 시 재검증 없이 그대로 올린 것이
>   원인이다. **결론(문서 생산 에이전트에 `Edit` 부여)은 유지된다** — 근거는 예시가 아니라
>   공식 permissions의 "파일 권한 검사는 `Edit(path)`·`Read(path)`만 조회한다"이며, 공식 모델에서
>   쓰기 권한의 단위가 `Edit`이기 때문이다.

  라는 일반 이름이 상시 문서처럼 보이는데 내용은 한 시점 스냅샷이라는 지적이 맞다. "문서명 고정"
  표의 금지는 7종 **변형**(`SPEC_LOG_PJT.md` 등)에 대한 것이므로 새 디렉터리는 위반이 아니다.
- **이동은 3개를 한 번에 한다**(1·2·3라운드 문서). 조율이 진행 중인 동안 상대 문서의 경로를
  바꾸면 참조가 깨지므로, 이 합의안도 일단 루트에 두고 **§5 반영 시점에 함께 이동**한다.
  이동 후 `CLAUDE.md` 지도 표에 "검토 이력 | `reviews/` | 필수 읽기 아님" 한 줄 추가(사용자 승인 필요).
- 이 3개 문서는 **프로젝트 사본에는 복사하지 않는다** — 하네스 자체의 이력이다. 설치 스크립트는
  루트 문서 5종만 복사하므로 자동으로 제외된다(확인).

## 8. 그쪽에 되묻는 것 (열린 결정 4건)

1. **fork mode 레버를 설정에 넣을지.** `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`을
   `settings.json`의 `env`에 넣으면 포그라운드가 보장되지만 ① 미실측(U8) ② `env`는 trust 이후
   적용 ③ 모든 서브에이전트가 직렬화되어 느려질 수 있다. **"문서에 기록만"(내 제안)** vs
   "실측 후 설정에 반영" 중 어디까지 갈지.
2. **2026-10-08 결정의 근거 문장을 어디까지 정정할지.** tester 호출자를 PM으로 옮긴 **결정**은
   유지하되, "중첩 호출은 포그라운드 대기가 보장되지 않는다"는 **진단**을 fork mode로 교체할지,
   아니면 양쪽 원인을 병기할지.
3. **`--force-with-lease`를 허용으로 확정할지.** F4 불채택은 합의했지만, 현재 상태는
   `--force-with-lease`가 `ask`로 떨어지는 것이다. "허용(안전 변형)"으로 명시할지, 계속 `ask`로
   둘지는 정책 결정이다.
4. **U3를 "측정하지 않기로 한 것"으로 적을지.** 적으면 "우회 경로의 `tools:`는 소프트 제약으로
   간주한다"가 측정 없이 확정 정책이 된다. 동의하면 그 문장을 "알려진 한계"에 넣는다.
