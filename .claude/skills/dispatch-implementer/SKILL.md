# 구현 에이전트 디스패치 골격

`ORCHESTRATION.md` "구현 에이전트 디스패치 원칙"의 실행판이다. 아래 7개 블록을 **전부** 넣는다.
하나라도 빠뜨리면 실제로 사고가 났던 자리다 — 각 블록에 그 근거를 적어 두었다.

## 1. 역할과 범위

- 에이전트 이름, 무엇을 하는지 한 문단.
- **이미 확인된 사실을 브리핑에 담는다.** 에이전트가 다시 조사하지 않게 한다.
  (레이트리밋으로 죽은 에이전트를 재디스패치할 때 PM이 작업트리 상태를 브리핑에 담았더니
  2회차가 1/3 토큰에 끝났다.)

## 2. 배타적 파일 소유권

```
## 당신이 배타적으로 소유하는 파일 (이 N개 외에는 수정 금지)
1. path/a
2. path/b
```

- **동시에 도는 다른 에이전트의 소유 파일을 명시**하고 "그쪽 때문에 보이는 실패는 당신 책임이
  아니니 보고에만 적고 고치려 들지 말라"고 쓴다.
- 소유 밖 결함을 찾으면 **고치지 말고 보고**하게 한다.

## 3. 검증 재현성 — 반드시 넣는다

```
- node_modules를 지우거나 이동하지 마세요.
- npm install류는 승인 게이트라 실행할 수 없습니다. 설치가 필요하면 BLOCKED로 분류하고 이유만 쓰세요.
- 당신이 보고하는 수치는 PM이 그대로 다시 돌려 같은 값이 나와야 합니다.
```

근거: 구현자 두 명이 `node_modules`를 지워 모듈 해석 오류로 **자기 검증을 스스로 깨뜨렸다.**
PM 프롬프트에 이 문장이 없었던 것이 원인이다.

## 4. 결정성 — 테스트를 만지는 디스패치면 필수

```
- 고정 시간 대기를 정착 수단으로 쓰지 마세요. 할 일이 없어질 때까지 비우세요.
- 고정 날짜를 주입하세요. new Date()는 날짜 경계에서 갑자기 깨집니다.
- 합격 기준은 "전체 스위트 연속 N회 전회 동일"입니다. N개 결과를 요약하지 말고 그대로 보고하세요.
```

근거: 테스트 헬퍼의 고정 4ms 대기 때문에 **전체 실행에서만, 매번 다른 단언이** 실패했다. PM이
"4회 연속 PASS"로 결정성을 보고했다가 뒤집혔다. **대기 시간을 늘리는 해법은 반려한다** — 느린
머신에서 재발하고 증상만 가린다. 고친 뒤에는 **부하를 걸어(코어 수의 2배 스핀 프로세스) 다시 잰다.**

## 5. 기준선 전달

`baseline-handoff` 스킬을 쓴다. 요약: **정상 동작인데 결함으로 오판하기 쉬운 것**을 번호 매겨
넘기고, **모든 수치에 그 수치의 기준을 붙인다.**

## 5-b. 절차는 프롬프트로 전달한다 — 프런트매터를 믿지 않는다

정의 파일의 `skills:`는 **네이티브·`@` 멘션 경로에서만** 적용된다. PM의 우회 경로
(`general-purpose` + "정의 파일을 따르라")에서는 프런트매터가 프롬프트 텍스트일 뿐이며,
`tools:`가 적용되지 않는 것이 **2026-10-16에 실측으로 확정**됐다(`tools: Read`로 좁힌 탐침에게
`Write`·`Edit`·`Bash`가 그대로 주어졌고 파일을 썼다). 따라서 우회 경로로 부를 때는:

- 에이전트가 따라야 할 절차를 **디스패치 프롬프트에 경로로 지정**한다 — 예: "개행을 확인할 때는
  `.claude/skills/eol-audit/SKILL.md`를 읽고 그 방법만 쓸 것(셸의 `grep -c $'\r'`·`sed '\r$'`는
  이 환경에서 틀린 답을 낸다)".
- 개행·인코딩을 건드리는 디스패치에는 `eol-audit`, 기준선을 넘기는 디스패치에는
  `baseline-handoff`를 같은 방식으로 지정한다.
- 도구 제한도 같은 처지다 — 우회 경로에서 "쓰지 말 것"은 **프롬프트 수준의 금지**이므로, 금지는
  6번 블록에 문장으로 적고 **기술적 강제가 필요하면 `permissions.deny`**(프로젝트 사본)에 넣는다.

## 6. 금지

- 시크릿 파일 열람 금지. 가능하면 `settings.json`의 `deny`로도 막는다 — **산문은 강제가 아니다.**
- 수정 금지 파일 목록.
- `git commit`/`tag`/`push`/`reset`, `npm install`류 = 승인 게이트.
- **단언을 느슨하게 고쳐 초록을 만드는 것은 실패로 간주**한다고 명시.
- 로그·보고에 시크릿 금지(에러 객체의 `config`에 API 키가 실린다 — `message`만 쓰게 한다).
- 주석 언어 규칙(`CODING_GUIDE.md` §3). 단 **코드에 실재하는 문자열의 인용은 원문 유지**다.

## 7. 보고 형식

- 압축 요구. "PM은 원본 데이터가 아니라 결론을 받는다."
- **수치 + PM이 그대로 돌릴 명령.**
- 결함 수정이라면 **"수정 전 빨강 → 수정 후 초록"을 수치로** 요구한다. 초록부터 보이는 단언은
  아무것도 보장하지 않는다.
- 마지막 항목은 항상 **"확신하지 못하는 것 — 추측하지 말고 미확정으로 올리세요"**.

## 디스패치 후 PM이 하는 일

- **보고를 그대로 믿지 않는다.** 수치를 직접 재현한다(실제로 보고와 다른 적이 있다).
- 에이전트가 **PM의 전제나 기준을 반박하면 먼저 실측한다.** 한 운행에서 PM 전제 3건이 그렇게
  뒤집혔고 셋 다 에이전트가 옳았다.
- 교차 소유권 때문에 아무도 못 고치는 실패가 남으면 **새 에이전트를 띄우지 말고 소유자를
  `SendMessage`로 재개**한다. 컨텍스트가 더운 상태라 훨씬 싸다.
