# 기준선 전달 규칙

서브에이전트는 맥락 없이 코드를 본다. **의도된 트레이드오프를 결함으로 판정**하거나, 반대로
**틀린 기대값을 단언으로 고정**한다. 기준선은 그걸 막는 장치다.

## 1. 모든 수치에 그 수치의 기준을 붙인다 — 가장 중요

틀린 예:

```
- Accel 이상치는 값이 전부 3.00입니다.
```

맞는 예:

```
- Accel 이상치 값은 기준에 따라 다릅니다:
  - 최신 500건 창(임계 2.9): 6건 전부 3.00
  - 전체 1,000줄(임계 2.86): 18건이 {2.9: 10건, 3.0: 8건}
```

실제 사고: PM이 "실측 기대값은 두 갈래"라고 명시해 놓고 **이 한 문장만 한쪽 기준으로** 보냈다.
테스트 작성 에이전트가 단언을 쓰다가 반박했고 재측정 결과 에이전트가 옳았다.
**기준이 두 갈래면 표로 만들어 섞이지 않게 한다.**

## 2. "이것은 결함이 아니다"를 근거와 함께 적는다

- 사용자가 수용한 트레이드오프 → **SPEC 줄 번호**를 같이 적는다
- 데이터 제약에서 오는 편향 → 왜 그런지 한 줄
- 화면마다 다른 라벨 같은 의도적 불일치 → 근거 문서 위치

## 3. 환경이 만드는 함정을 적는다

- ICU 의존 포맷은 환경에 따라 달라져 단언 불가 — 대체 함수를 알려준다
- 프레임워크 템플릿 주석이 렌더 결과에 남아 정적 문자열 검사를 뒤집는다
- 동일값 묶음(tie) 때문에 "정확히 N%" 단언은 틀린 단언이다

## 4. 도달 불가 상태를 적는다

"이 상태는 단일 필터로 도달할 수 없으니 직접 주입하라"처럼 **대체 경로까지** 준다.
안 적으면 에이전트가 "확인 못 함"으로 올리거나 틀린 방법으로 도달했다고 착각한다.

## 기계적 합격 기준의 경고

글자 단위 기준은 규칙의 취지를 벗어나게 만든다. 실제 사고: 주석 언어 규칙(산문은 영어)을
**"주석에 한글 문자 0개"로 번역**해 넘겼더니 코드에 실재하는 UI 문자열 인용까지 번역되어
주석이 코드와 어긋났다. 세 에이전트가 **각각 독립적으로** 이 기준을 반박했다.

- 기준은 **취지로** 쓴다: "한국어 **산문** 0줄, 남은 한글은 따옴표 안 인용과 식별자 태그뿐"
- **여러 에이전트가 같은 지점을 반박하면 기준이 틀린 것이다.** 설득하지 말고 실측한다.

## 기준선은 자산이다

한 운행에서 모은 기준선은 다음 운행에서도 대부분 유효하다. 디스패치마다 다시 쓰지 말고
프로젝트 문서에 모아 두고 인용한다.
